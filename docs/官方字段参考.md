# 官方配置字段参考（ACS 0.995）

本文件说明各 XML 配置里**每个字段是什么、写什么值、写了会怎样**。
配套的三份文档分工如下：

| 文档 | 内容 | 怎么用 |
|---|---|---|
| `docs/官方字段参考.md`（本文） | 字段语义、取值范围、坑 | 写配置前查 |
| `docs/官方字段统计.md` | 原版 `Settings/` 里每个字段的**真实出现次数与取值抽样** | 不确定能不能写时查原版有没有先例 |
| `docs/属性速查.md` | 全部角色属性名（中文名/类型/基础值/上下限） | 写 Modifier 的 `<li Name>` 时查 |

两份统计表由 `tools/gen_field_docs.py` 扫描原版生成，**随时可重跑**：

```bash
python tools/gen_field_docs.py
```

字段定义以反编译源码为准：`C:\Users\28040\AppData\Local\Temp\acs_src\XiaWorld\*Def.cs`。
下文的「类型」栏中，`float`/`int` 字段在 C# 里默认值多为 `float.MinValue`/`int.MinValue`，
表示「未配置」，引擎按缺省逻辑处理，**不等于 0**。

## 1. 通用约定

1. **文档头**：每个 XML 文件首行必须是 `<?xml version="1.0" encoding="utf-8"?>`，随后是固定根节点（如 `<Gongs>`）；
   根节点与 `GameMain` 期待的名字不一致时，整个文件会被静默忽略。
2. **标签大小写**：属性名（`Name=`、`Level=`）区分大小写；元素名（`<DisplayName>`）也必须完全一致。
   官方有一处**已知拼写错误**：`Neck/Kind="Gold"` 下的资源子元素叫 `<Esoterocas>`（不是 `<Esotericas>`）。
3. **布尔**：一律写 `0` / `1`。
4. **列表**：要么 `<li>值</li>` 序列，要么整段逗号字符串（如 `Line`、`FiveBaseNeed`），按字段说明。
5. **富文本**：`DisplayName`/`Desc`/`EffectDesc` 支持 UBB，用 `[color=#RRGGBB]…[/color]`、`[size=10]…[/size]`。
   **不要写 HTML `<font>`**，不保证被解析。
6. **默认值**：C# 里 `float.MinValue` 之类的字段没写时保持哨兵值；**依赖它做除法或比较前必须判空**，
   很多「数值变成 0 / 百分比变成 -inf」的怪现象都来自这里。
7. **继承**：`Parent` 指向另一个 Def 的 `Name`，只覆盖显式写了的字段；基础 Def 名见 §10。
8. **引用完整性**：`AddModifier`、`Esoterica`、`Gong`、`Magics`、`ItemName` 等引用**必须指向存在的 Def**，
   否则该条目（有时是整个文件）加载失败，日志里往往只有一行 `can not find xxx`。

## 2. 功法根节点 `<Gong>`

文件位置：`Settings/Practice/Gong/*.xml`，根节点 `<Gongs><List>…</List></Gongs>`。
定义源码：`XiaWorld/GongDef.cs`。

| 字段 | 类型 | 必填 | 说明与取值 |
|---|---|---|---|
| `Name` | string | 是 | 功法唯一 ID，参悟树 `<Gong>`、秘籍、调试命令都用它引用；建议前缀自建名，如 `Gong_YanTian` |
| `Parent` | string | 否 | 继承另一功法 |
| `DisplayName` | string | 是 | 界面显示名 |
| `Desc` | string | 否 | 功法总描述（多行 UBB） |
| `SelectDesc` | string | 否 | 选择功法界面里的长描述（原版 24 个里 16 个有写） |
| `FiveBaseNeed` | string | 是 | 5 个整数，五行灵根需求，顺序 `金,木,水,火,土`；`-1` 表示不限。原版常见 `-1,-1,-1,-1,-1`、`-1, 7, 5, 6, -1`、`4, 6, -1, 6, 3`。**必须正好 5 个数**：`GetFiveBaseNeed` 按 `array.Length` 循环，写 6 个会越界 |
| `ElementKind` | 枚举 | 是 | `None / Jin / Mu / Shui / Huo / Tu / Chaos`。⚠️ `None` 时 `GameDefine.GetElementColor` 返回**纯黑**，飞升/神修若走世界模型染色会显示为黑剪影（仅 `npc.IsGod` 路径实测触发）；纯标记性功法也建议给一个具体五行 |
| `SkillSetName` | string | 仙修必写 | **C# 侧无任何消费点**（只做引用桥接），原版 17/17 全为空标签 ⇒ 留空即可 |
| `Skill` | li 列表 | 仙修必写 | 该功法可用的「技艺」动作，7 个标准值：`chumo`（除魔）/`jiangdao`（降道）/`guanding`（灌顶）/`ciqi`（赐器）/`kaiguang`（开光）/`cuiti`（淬体）/`bihu`（庇护）。少写不会崩，但对应动作在人物面板里不可用 |
| `GongKind` | 枚举 | 否* | `Dao`（仙修，默认可省略）/`God`（神修）/`Body`（体修）/`Soul`（魂修）。体修、神修**必须**写 |
| `Stages` | 容器 | 是 | 下面的 `<Stage>` 列表，见 §3 |
| `Magic` | li 列表 | 否 | 功法自带的初始神通 |
| `GodGuards` | li 列表 | 神修 | 神卫 |
| `SuperParts` | li 列表 | 体修 | 超品部位 |
| `QuenchingMethods` | li 列表 | 体修 | 淬体法 |
| `BodyAttitude` | string | 体修 | 体修姿态 |
| `IllustratedHandLabel` | 枚举 | 否 | 原版仅 `Dele` 一值 |
| `TexPath` | string | 否 | 功法图标贴图路径 |
| `Hide` | int | 否 | 1–3，隐藏该功法不出现在选择列表 |
| `Empty` | int | 否 | 原版仅 1 例，占位用法 |
| `YinYang` | int | 否 | 原版仅 1 例，阴阳属性 |

## 3. 功法阶段 `<Stage>`

| 字段 | 类型 | 必填 | 说明与取值 |
|---|---|---|---|
| `Name` | string | 是 | 阶段 ID（`Stage1`…）；同一功法内唯一 |
| `Level` | int | 是 | **境界档位**，不是序号。引擎用 `GetGongStageLevel` 做纯 `>=` 比较：`>=10 → God`、`>=7 → Dan2`、`>=4 → Dan1`、其余 `Qi`。原版 142 个 Stage 覆盖 1–12 全部取值 ⇒ **任意 1–12 都安全**；超出 12 不会报错但 UI/天劫逻辑可能不认 |
| `DisplayName` | string | 是 | 阶段名（人物面板展示） |
| `Desc` | string | 否 | 阶段说明 |
| `Value` | float | 是 | 该阶段的**突破所需修行值**，原版 1–50,000,000；相邻阶段应递增，否则会瞬间连跳 |
| `Necks` | 容器 | 是 | 阶段内的瓶颈关卡，见 §4；**不要留空容器**，`Necks` 为 null 时引擎多处 foreach 会 NRE |

> 阶段数量：原版最少的功法 4 段，最多的 `Gong_DaNneg`/`LingShou`/`YaoShou` 12 段。
> 阶段 >9 时人物面板显示会拥挤甚至溢出，社区建议控制在 9 段以内。

## 4. 瓶颈 `<Neck>`（九种 Kind）

`<Neck Location="0.3" Kind="Chance">`：`Location` ∈ (0, 1]，表示**本阶段修为的百分比位置**，
必须严格递增且最后一个为 `1`（原版 232 个 Neck 的 `Location` 末项全部为 1）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `DisplayName` | string | 关卡名 |
| `Desc` | string | 关卡说明（多行以 `\n` 写） |
| `CostTime` | float | 突破耗时（原版 1–1200）；越大越久 |
| `SuccessChange` | float / string | 成功率。可写 `0.5` 这样的常量，也可写属性表达式（如 `Intelligence_2_25_5`，格式 `<属性>_<系数>_<常数>_…`）；**不确定就写小数** |
| `FailedChangeAdd` | float | 失败一次后成功率增量（原版 0.05–0.2） |
| `ExploreValue` | float | 历练倍率（`Kind="Explore"` 用） |
| `ThunderValue` | float | 雷劫强度（`Kind="Thunder"`/`God` 用，原版 8,000–1,250,000） |
| `NeckCountdown` | float | 天劫倒计时（秒，原版 1,800–18,000） |
| `AddModifier` | string | 通过后永久附加的 Modifier 名 |
| `FailModifier` | string | 失败时附加的 Modifier |
| `Damages` | 容器 | 失败伤害：`<li PartKind="Meridian" Name="ElixirFieldShock" Rate="0.5"/>` |
| `ItemCost` | 容器 | 突破消耗物品：`<Item name="Item_Dan_JingYuan2"/>` |
| `ResourceCost` | 容器 | 突破消耗资源：`<Resource kind="Age" value="10"/>`，`kind` ∈ `Ling / Experience / Understand / Stage / Age` |
| `Esoterocas` | 容器 | `Kind="Gold"` 专用（官方拼写错误，照抄） |

各 Kind 的**必需**子元素：

| Kind | 含义 | 必填 | 常配 |
|---|---|---|---|
| `Chance` | 普通概率突破 | `CostTime`、`SuccessChange` | `FailedChangeAdd`、`Damages`、`ItemCost`、`ResourceCost`、`AddModifier` |
| `Explore` | 历练事件突破 | `ExploreValue` | `SuccessChange` |
| `Work` | 工作/劳作突破 | `CostTime` | — |
| `Gold` | 黄金/资源门槛 | `Esoterocas` 或 `ResourceCost` | `AddModifier` |
| `Thunder` | 雷劫 | `ThunderValue`、`NeckCountdown` | `AddModifier`（常挂护体类） |
| `God` | 神修天劫 | `ThunderValue`、`NeckCountdown` | — |
| `GodCity` | 神国建设 | — | `AddModifier` |
| `FuPractice` | 符修 | `ItemCost` | — |
| `Die` | 必死/剧情 | — | `Damages` |

> 只想「按修为自动升境」的最简写法：每个 Stage 放一个 `Kind="Chance"`、`Location="1"`、
> `CostTime` 20–50、`SuccessChange 1`，不要写 `Thunder`。想加天劫再补 `Thunder` 关。

## 6. 参悟树节点 `<Node>`

文件位置：`Settings/Practice/Tree/*.xml`；源码 `XiaWorld/NPCSkillTreeDef.cs`。

| 字段 | 类型 | 必填 | 说明与取值 |
|---|---|---|---|
| `Name` | string | 是 | 节点 ID，全局唯一 |
| `Gong` | string | 是 | 所属功法（必须是存在的 `<Gong Name>`），决定出现在哪棵树 |
| `Esoterica` | string | 是 | 该节点学到的秘籍名（**必须是存在的 `<Esoterica Name>`**）。一个节点一本，不要多节点共用同一本秘籍，否则「学一个点亮一片」 |
| `DisplayName` | string | 是 | 节点显示名 |
| `Level` | 枚举 | 是 | **显示行**：`Qi / Dan1 / Dan2 / God / God2`，界面按 `Level-1` 取行（`Qi=1` 起，`None=0` 非法）。改它只影响排版，**不影响学习门槛** |
| `Index` | int | 是 | **行内列号，0–11**，同一 Level 内唯一且不要超过 11（每行固定 12 格，越界节点不显示） |
| `Line` | string | 是 | **恰好 8 个** 0/1/2 组成的连线表，如 `0,0,0,0,0,0,0,0` |
| `PreUnit` | li 列表 | 否 | 前置节点，未点亮时该节点不可点 |
| `MutexUnit` | li 列表 | 否 | 互斥节点，点亮后本节点不可点 |
| `Depth` | int | 否 | 0 = 主视图，1 = 深层视图；树上有「深浅」切换按钮，`Depth` 与当前视图不符的节点会隐藏 |
| `LingMax` | float | 否 | 学习所需的额外灵气上限门槛 |
| `GoldLevel` | int | 否 | 所需黄金/资源等级 |
| `GodCount` | int | 否 | 神修相关计数门槛 |
| `DaoHang` | int | 否 | 道行门槛（原版 578 个节点**未使用**，建议 0） |
| `FiveBase` | string | 否 | 五行需求，逗号分隔 |
| `Skills` | 容器 | 否 | 节点附带的技艺数据 |
| `Layers` | li 列表 | 否 | 分层节点 |

**降低学习门槛的正确做法**：改秘籍的 `GLevel` 与 `Difficulty`，清空 `PreUnit`；
**不要**把所有节点压到同一个 `Level`——那只会让它们挤在同一行，其余行空白。

## 8. `<Modifier>`

文件位置：`Settings/Modifiers/*.xml`；源码 `XiaWorld/ModifierDef.cs`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `Name` | string | 唯一 ID |
| `DisplayName` / `Desc` | string | 展示 |
| `Type` | 枚举 | 常用 `Normal`；还有 `Hide` 等 |
| `MaxStack` | int | 最大叠加层数；`0` 表示不限 |
| `Duration` | float | 持续时间（秒）；**`-1` = 永久** |
| `Display` | int | 是否在人物面板展示（1/0） |
| `Properties` | 容器 | 属性修正，见下 |
| `Skills` | 容器 | 给予技能 |
| `Damages` | 容器 | 施加伤害 |
| `Modifiers` | li 列表 | 附带其他 Modifier |
| `SpecialFlags` | li 列表 | 特殊状态，如 `FLAG_NOMAGIC`、`FLAG_NOLING`、`FLAG_THUNDERING` |
| `GlobleModifiers` / `WorldFlags` | li 列表 | 全局修正 / 世界旗标 |
| `UnLockMagic` | li 列表 | 解锁神通 |
| `UnLockGodGuards` / `UnLockGodCityBuildings` | li 列表 | 神修解锁 |
| `Class`/`ClassName`/`LuaClassName` | string | 自定义实现 |
| `EffectBind` | 容器 | 绑定特效 |

属性修正写法：

```xml
<Properties>
  <li Name="MaxAge" AddV="10"/>
  <li Name="NpcLingMaxValue" AddP="2.5"/>
  <li Name="DeepPracticeSpeedSpecialCoefficient" BAddP="0.5"/>
</Properties>
```

| 子属性 | 含义 |
|---|---|
| `AddV` | 加减**当前值**的绝对值 |
| `AddP` | 加减**当前值**的百分比（原版写法不统一，既有 `2.5` 也有 `100`，改动需实机验证） |
| `BAddV` | 加减**基础值**的绝对值 |
| `BAddP` | 加减**基础值**的小数比例（原版实测 0.002–1.75）⇒ `BAddP="1"` ≈ 基础值 +100% |

常用属性（全表见 `docs/属性速查.md`）：

| 属性 | 用途 | 基础值 |
|---|---|---|
| `NpcLingMaxValue` | 灵气上限 | 500 |
| `MaxAge` | 寿元 | — |
| `DeepPracticeSpeedSpecialCoefficient` | 修炼速度倍率 | 1 |
| `InspirationCoefficient` | 领悟悟性倍率 | 1 |
| `LingAbsorbSpeed` | 灵气吸收 | — |
| `NeckCountdownAddV` | 瓶颈倒计时推迟（秒） | 0 |
| `NpcFight_FabaoNum` | 可携带法宝数（法宝格） | — |

## 12. 症状 → 根因 → 修法

| 症状 | 根因 | 修法 |
|---|---|---|
| 参悟树**整片空白** | 某本秘籍 `StarLevel` ≥ 3，控制器索引越界，第一个节点就抛异常，循环中断 | `StarLevel` 改 0/1/2 |
| 参悟树只亮一行、其余空 | 所有节点写了同一个 `Level`，或 `Index` >11 | 按境界分行、行内 `Index` 从 0 连续 |
| 点了神通没反应也不报错 | `Type="Class"` 缺 `ClassName`，或 `GetMagic` 名与 `Name` 不一致 | 补 `<ClassName>`，核对名字 |
| 学完秘籍没获得能力 | 秘籍没挂 `<Magics>`，或神通 `SelectTarget` 与实际用法不符 | 挂 `<Magics><li>…</li></Magics>` |
| Modifier 写了没效果 | `<li Name>` 属性名不存在（拼错/自造） | 在 `docs/属性速查.md` 里核对 |
| 数值爆炸（+30000%） | `BAddP` 当成百分数写了（应为小数比例） | `300` → `3`，`200` → `2` |
| 面板错乱但日志无异常 | Unity 异常只进 `Player.log`；`Wnd_NpcInfo.OnShowUpdate` 连续刷 5 个 Panel 无 try/catch | 看 `output_log.txt` / `Player.log` |
| 存档读回后数据丢失 | `Lib:Serialize` 只支持 number/boolean/string/table，nil 不可存 | 存档用纯 KV，对象存 ID |
| 每秒刷错误 | 对 C# List 用了 `#` | 改 `.Count` 且下标从 0 开始 |
