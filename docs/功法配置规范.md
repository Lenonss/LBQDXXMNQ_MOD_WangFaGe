## 1. 文件与目录

| 内容 | 路径（相对 mod 根） | 根节点 |
|---|---|---|
| 功法本体 | `Settings/Practice/Gong/<任意名>.xml` | `<Gongs><List><Gong>` |
| 参悟树 | `Settings/Practice/Tree/<任意名>.xml` | `<SkillTree><List><Node>` |
| 秘籍 | `Settings/Esoterica/<任意名>.xml` | `<Esotericas><List><Esoterica>` |
| 特性/属性 | `Settings/Modifiers/<任意名>.xml` | `<ModifierDefs><List><Modifier>` |
| 神通 | `Settings/Practice/Magic/<任意名>.xml` | `<Magics><List><Magic>` |
| 法宝配方 | `Settings/Practice/FabaoFormula/<任意名>.xml` | `<FabaoFormulas><List><Fabao>` |
| 物品 / 建筑 | `Settings/ThingDef/Item|Building/<任意名>.xml` | `<ThingDefs><List><ThingDef>` |
| 建造菜单 | `Settings/UI/MainList/<任意名>.xml` | `<MainList><List><Data>`（必须是 `MainList/` 目录下的文件） |

约定：

- 文件名随意，但**同目录内不要与其它 mod 重名**（mod 加载是合并式，同名文件后者覆盖前者）。
- 编码 UTF-8（带不带 BOM 均可），换行 LF。
- 所有 `Name` 属性是全局唯一键，建议加 mod 前缀（本 mod 用 `WFG_`）。
- **改 XML 必须重启游戏**，热重载只对 `Scripts/` 部分生效。

## 2. Gong 根节点

```xml
<Gongs><List>
  <Gong Name="WFG_Gong_YanTian">
    <DisplayName>衍天诀</DisplayName>
    <Desc>…</Desc>
    <SelectDesc>…</SelectDesc>
    <FiveBaseNeed>-1,-1,-1,-1,-1</FiveBaseNeed>
    <SkillSetName></SkillSetName>
    <ElementKind>None</ElementKind>
    <Skill><li>chumo</li>…</Skill>
    <Stages>…</Stages>
  </Gong>
</List></Gongs>
```

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `DisplayName` | 是 | 任意 | 功法名 |
| `Desc` | 是 | 任意，支持 UBB `[color=#RRGGBB]…[/color]`、`[size=N]…[/size]`、`\n` | 详情页正文 |
| `SelectDesc` | 是 | 任意 | 选择功法时的确认文案 |
| `FiveBaseNeed` | 是 | **恰好 5 个整数**，`-1` 表示不限 | 顺序＝金木水火土。**超过 5 个会 IndexOutOfRange**（`GongDef.GetFiveBaseNeed` 循环上界是 `array.Length`） |
| `SkillSetName` | 是（可空） | **恒为空标签** | 原版 17/17 全空；C# 侧零消费点；填内容没有任何作用 |
| `ElementKind` | 是 | `None/Jin/Mu/Shui/Huo/Tu`（`Chaos` 存在但**不要用**） | `None` 合法（原版 14 个功法在用）。副作用见 §7 |
| `Skill` | 仙修必填 | 7 个动作 `chumo/jiangdao/guanding/ciqi/kaiguang/cuiti/bihu` | 少写不报错但门派工作会缺项；`checker` 会警告 |
| `Stages` | 是 | ≥2 个 `Stage` | 见 §3 |
| `GongKind` | 否 | `Body` / `God` | **仙修不要写**；写了就变体修/神修 |

## 3. Stage（境界段）

```xml
<Stage Name="Stage1" Level="1">
  <DisplayName>引灵入体</DisplayName>
  <Desc>…</Desc>
  <Value>1800</Value>
  <Necks>
    <Neck Location="0.5" Kind="Chance">…</Neck>
    <Neck Location="1"  Kind="Chance">…</Neck>
  </Necks>
</Stage>
```

- `Level`：**int，1–12**。原版 142 个 Stage 里 1..12 每个值都有真实用例（`Level="1"`×5、`"7"`×9、`"8"`×6、`"10"`×7），任意值都安全；`GameDefine.GetGongStageLevel` 只做 `>=` 比较（≥10→God、≥7→Dan2、≥4→Dan1、否则 Qi）。
- **段数与 Level 的对应关系决定流派手感**：
  - 原版主流是 4 段（3/6/9/12）或 5 段（3/5/6/9/12）。
  - 段数 >9 时个别界面显示不全（社区实测「最高显示 9 个阶段」）。
  - **Level 必须严格递增**，末段建议 `12`（渡劫段通常就在这里）。
- `Value`：该境界需要的修炼值，正整数，逐段递增（原版单段 1000–80000 量级）。
- `<Necks>`：**必须存在且非空**。代码里有 `foreach (… in gongStage.Necks)` 无 null 检查（`Wnd_SelectGongs2.cs:497`、`NpcPractice.cs:1923`），漏写 `<Necks>` 等于选功法界面 NRE。
- 每个 Stage 建议 2–3 个 Neck：`Location=0.5` 一个小关，`Location=1` 一个大关。

### 3.1 Neck 九种 Kind 与各自必需子元素

| Kind | 用途 | 必需/可用子元素 |
|---|---|---|
| `Chance` | 常规概率突破 | `CostTime`、`SuccessChange`、`FailedChangeAdd`、`AddModifier`、`FailModifier`、`ResourceCost`、`ItemCost`、`Damages` |
| `Explore` | 需要历练/探索 | `ExploreValue` |
| `FuPractice` | 服丹/符修 | 参考原版 `Gong_*` 对应段 |
| `God` | 神修/飞升大关 | `ThunderValue`、`NeckCountdown` |
| `GodCity` | 神国 | 见 `GongKind=God` 功法 |
| `Gold` | 金丹 | `AddModifier`（原版填 `Gong_Gold`） |
| `Thunder` | 天劫 | `ThunderValue`、`NeckCountdown` |
| `Work` | 工作/炼制 | 见原版 |
| `Die` | 死亡/夺舍 | 见原版 |

- `Location`：`(0,1]` 的小数，同段内**必须递增**。原版实测取值 0.01/0.1/0.15/0.2/0.25/0.3/0.33/0.35/0.4/0.45/0.5/0.6/0.66/0.7/0.8/0.85/0.9/0.95/0.99/1，最后一定是 `1`。
- `SuccessChange`：数字，或属性表达式（如 `Intelligence_2_25_5`、`Qi_1_5_25`）。
- 天劫段：`ThunderValue` 是雷劫强度（原版 10000–520000），`NeckCountdown` 是倒计时天数（4900/3000 量级）。

## 4. Modifier（属性/特性）

```xml
<ModifierDefs><List>
  <Modifier Name="WFG_Mod_YanTian_Fly" Type="Normal">
    <DisplayName>灵子飞升</DisplayName>
    <MaxStack>0</MaxStack>
    <Duration>-1</Duration>
    <Display>0</Display>
    <Properties>
      <li Name="MaxAge" AddP="300"/>
      <li Name="NpcLingMaxValue" BAddP="200"/>
    </Properties>
  </Modifier>
</List></ModifierDefs>
```

- `Type`：`Normal` 为常规。其它值见 `Settings/Modifiers/` 原版。
- `Duration=-1` 永久；正数为持续天数。
- `MaxStack`：0 表示不叠加层数上限（原版多数填 0）。
- `<li>` 的四种写法：`AddV`（加绝对值）、`AddP`（加百分比）、`BAddV`（加基础值）、`BAddP`（加基础值百分比）。
- **属性名必须存在于 `Settings/Property/*.xml`**，否则整条被静默忽略（不报错）。常用：
  `MaxAge`、`NpcLingMaxValue`（灵气上限，Base 500）、`NeckCountdownAddV`（天劫倒计时推迟，Max 99999999）、`DeepPracticeSpeedSpecialCoefficient`（修炼速度，Base 1，Min 0.5）、`InspirationCoefficient`、`LingAbsorbSpeed`、`NpcFight_FabaoNum`（法宝格）。

## 5. 参悟树（SkillTree）

```xml
<Node Name="WFG_Tree_YanTian_A0" Gong="WFG_Gong_YanTian">
  <Esoterica>WFG_Eso_YanTian_Gong</Esoterica>
  <DisplayName>万法总纲</DisplayName>
  <Level>Qi</Level>
  <Index>0</Index>
  <Line>0,0,0,0,0,0,0,0</Line>
  <PreUnit></PreUnit>
  <MutexUnit></MutexUnit>
  <FiveBase>0,0,0,0,0</FiveBase>
  <LingMax>0</LingMax>
  <GoldLevel>0</GoldLevel>
  <GodCount>0</GodCount>
</Node>
```

| 字段 | 规则 |
|---|---|
| `Gong` | **必须是已存在的功法 Name**，悬空会让整棵树/该节点异常 |
| `Esoterica` | 必须是已存在的秘籍 Name；节点显示的就是这本秘籍 |
| `Level` | 枚举 `None/Qi/Dan1/Dan2/God/God2`，**决定显示在哪一行**（`Qi`=第 1 行 … `God`=第 4 行）——它**不是**学习门槛 |
| `Index` | **行内格位，0–11**（每行固定 12 格）。同一 `Level` 行的 `Index` **不可重复**，否则互相覆盖 |
| `Line` | **恰好 8 个数字**（0/1/2），连线的 8 个方向 |
| `PreUnit` | 前置节点 Name 列表，空表示无前置 |
| `MutexUnit` | 互斥节点 Name 列表 |
| `Depth` | 0/1 两页，由界面左上角按钮切换；**全填 0 时另一页是空的**（不是 bug） |

铁律：

1. **一本秘籍只挂一个节点**。多个节点共用同一 `<Esoterica>` → 学一本全部变「已习得」，看起来像界面错乱。
2. **同一 `Level` 行的节点数 ≤ 12**，`Index` 连续从 0 起最好看。
3. 想「全部下放到练气期」，改的是秘籍的 `<GLevel>` 与 `<Difficulty>`，**不是**节点的 `<Level>`（后者只挪行位）。

## 6. 秘籍（Esoterica）与神通（Magic）

```xml
<Esoterica Name="WFG_Eso_YanTian_Heal">
  <DisplayName>自愈程序</DisplayName>
  <Icon>res/Sprs/ui/icon_zhoutian01</Icon>
  <StarLevel>2</StarLevel>
  <Difficulty>1</Difficulty>
  <Desc>…</Desc>
  <GLevel>Qi</GLevel>
  <Element>None</Element>
  <Type>Skill</Type>
  <Magics><li>WFG_Magic_HealOff</li></Magics>
  <EffectDesc>[size=10][color=#D06508]习得神通：…[/color][/size]</EffectDesc>
</Esoterica>
```

- **一个神通 = 一枚按钮**：想让按钮随状态换文案与图标，就拆成两个 `Magic`（如 `WFG_Magic_HealOff` / `WFG_Magic_HealOn`，`ClassName` 指向同一段 Lua），运行时用 `npc.PropertyMgr.Practice:RemoveMagic/AddMagic` 切换 `Practice.Magics` 里的条目。人物面板每帧 `UpdateBnts()` 重建神通按钮，改完下一帧就生效；`NpcMagicBnt` 的文案/图标按**神通名**缓存，所以不能靠改同一个 `MagicDef` 的 `DisplayName`/`Icon` 来换态。
  - **Lua 方法要绑到 `<ClassName>` 上，不是神通名**：引擎执行 `MagicBase.Init` → `GameMain:GetMod('MagicHelper'):NewMagicClass(def.ClassName)`（`XiaWorld.Magic/MagicBase.cs:13`，调用方 `PracticeMgr.cs:1189`），`MagicHelper:NewMagicClass(name)` 内部就是 `Lib:NewClass(GetMagic(name))`（游戏 `Scripts/Magic/magic.lua:35`）。所以 `WFG_Magics.lua` 里要 `bind(tbTable:GetMagic("<ClassName>"))`。绑成神通名只会得到一张没人用的空类，基类默认 `EnableCheck` 恒真、`MagicEnter` 空实现、`MagicStep` 返回 1 ⇒ 按钮能点、点击毫无反应（本项目自愈按钮曾因此“关不掉”）。两个 `Magic` 共用同一个 `ClassName` 是允许的，方法写一份即可。
- **`Practice` 挂在 `PropertyMgr` 上，不在 `Npc` 上**：引擎只给 `NpcPropertyMgr` 注册了 `Practice` 获取器（`XLua/ObjectTranslator.cs:52386`），`Npc` 上只有 `PropertyMgr`（`:53802`）。所以必须写 `npc.PropertyMgr.Practice`。写成 `npc.Practice` 在 XLua 里**不报错、直接返回 nil**，`pcall` 也包不住（取成员失败不抛异常），于是 `AddMagic/RemoveMagic/CheckMagic` 全部静默空转——本项目自愈按钮曾因此完全不生效，并且旧神通名留在 `Practice.Magics` 里消不掉，面板每帧 `GetMagicDef` 失败把日志刷成 `cant find magic:...`（约 60 行/秒）。判断这类问题最快的办法：日志里同一句 `[ERROR]` 高频重复 + 对应功能“什么都没发生”。
- **`StarLevel` 只能 0/1/2**。它被界面直接当成 FairyGUI 控制器下标（`Wnd_GongSkillTree.cs:137`，页数=3），填 3 会 `set_selectedIndex` 越界 → **整棵参悟树空白**（本项目已踩过）。
- `GLevel` 是**学习门槛**（`NpcPractice.CheckCanLearnEsoteric` 里 `sysEsoterica.GLevel > GongStateLevel` 就拒学）：`Qi/Dan1/Dan2/God`。
- `Difficulty` 越小越容易学（1 最低），同时降低所需参悟经验。
- `Type`：`Gong/Dan/Fabao/Skill/Barrier/Refining/None`。
- `Icon` 有两种写法：①引用原版贴图 `res/Sprs/ui/icon_*`；②引用 mod 自带贴图，写**单段文件名且带扩展名**（如 `wfg_skill_derive.png`），文件放在 mod 目录 `Resources/<同名>.png`。秘籍与神通共用这套规则。
- **自带贴图的判别方式**：`NewGetSprite.GetSprite` 先看路径里有没有 `/`——有斜杠就只查原版图集（`Resources.LoadAll/Load<Sprite>`），**不会查 mod 目录**；无斜杠才走 `ModsMgr.LoadTexture2D("Resources/" + path)` → `GetPath` 拼 `<mod>/Resources/<path>` → `File.Exists` 判存在（所以扩展名不能省）。
- 自制图标建议 128×128、PNG、带透明通道；不透明底图（JPG）在圆形按钮里会露出方块边角。
- 富文本一律 UBB：`[color=#D06508]`、`[size=10]`；**不要用 HTML `<font color=…>`**。

### 神通

```xml
<Magic Name="WFG_Magic_Derive" Type="Class">
  <DisplayName>衍天·解析</DisplayName>
  <Desc>…</Desc>
  <Icon>wfg_skill_derive.png</Icon>
  <Kind>None</Kind>
  <CostLing>0</CostLing>
  <SelectMode>Single</SelectMode>
  <SelectTarget>Item</SelectTarget>
  <ClassName>WFG_Magic_Derive</ClassName>
</Magic>
```

- **`Type="Class"` 必须写 `<ClassName>`**，否则 Lua 侧 `GetMagic(名字)` 拿不到绑定，点击神通无反应且不报错。`ClassName` 与 Lua 里 `tbTable:GetMagic("…")` 的参数一致。
- `SelectMode`：`None` / `Single`。`SelectTarget`：`Item`、`Npc`、`Point|InLight|Walkable` 等，官方实有 23 种写法。
- `CostLing` 为施法灵气消耗；`Param1..3`、`sParam1..3` 是自定义参数。
- `Icon` 同样支持 mod 自带贴图：写单段文件名（`wfg_skill_derive.png`），文件放 `Resources/` 下；不要写 `Resources/xxx` 这种带斜杠的路径，会退化成原版图集查找而显示空白。

## 7. ElementKind 的隐藏副作用

`GameDefine.GetElementColor(None)` **硬编码返回 `Color.black`**。唯一消费点：`NpcView.Change2YiTui()`（`NpcView.cs:1944`）在 `npc.IsGod`（飞升成灵体）时用它设置 `_FlowColor`。

⇒ **`ElementKind=None` 的功法，其门人飞升成灵体后世界模型会变成纯黑剪影。** 这是引擎行为，不是配置错误；若介意，把 `ElementKind` 改成 `Mu`/`Jin` 等五元素之一即可（`Chaos` 不要用：`ElementColors[kind-1]` 会越界）。

## 8. 数值与文案书写规则

- `Desc`/`EffectDesc` 里的换行写 `\n`（XML 里是字面量反斜杠 n）。
- 富文本用 UBB，闭合标签别漏。
- 数字不要写千分位、不要写单位；小数用 `.`。
- 中文全角标点可以，但**不要混入 NBSP 或全角空格**。

## 10. 故障 → 根因 → 修法

| 症状 | 根因 | 修法 |
|---|---|---|
| 参悟树**整片空白** | 任一秘籍 `StarLevel ≥ 3`（控制器下标越界，首个节点即抛错） | 全部改 0/1/2 |
| 参悟树只有一行有图标，其余行空 | 把节点 `<Level>` 全压成同一枚举（界面按 Level 分行） | 保持各境界分散 |
| 学一本秘籍，多个格子一起变「已习得」 | 多节点共用同一 `<Esoterica>` | 一本一节点 |
| 点神通无反应、也不报错 | `Type="Class"` 缺 `<ClassName>` | 补 `ClassName` |
| 选功法界面报错/无内容 | 某个 `Stage` 漏写 `<Necks>` | 补空/实内容 |
| `FiveBaseNeed` 越界崩溃 | 写了 5 个以上整数 | 只写 5 个 |
| 飞升成灵体后角色变**纯黑剪影** | `ElementKind=None` → `GetElementColor` 返回黑色 | 改用五元素之一 |
| 境界名字与预期不符（如第 9 段显示「元神期」） | `GetGongStageLevel` 只按 `Level>=` 映射五档 | 调整 `Level` 数值，别指望自定义档名 |
| 「在世仙人」不出现 | 只由 `GodCount>0`（渡劫成功）触发 | 正常渡劫 |
| 改 XML 后游戏内无变化 | XML 只在启动时解析 | 重启游戏 |
