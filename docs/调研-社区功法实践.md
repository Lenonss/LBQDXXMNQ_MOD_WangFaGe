## 2. 社区教程要点（逐条 · 带出处 · 「必须/否则」原样保留）

### 2.1 英文社区权威文档：`iguanacore/acs-modding-guide-iguana`（目前唯一成体系的 Gong 字段文档）

出处：https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/information/Laws(Gong).md

1. **`SkillSetName` 是死字段**：原文 "SkillSetName - Not used, leave it as it is."（未使用，保持原样即可）。
2. **`Name` 必须唯一**：原文 "Name - Internal identifier for the Gong, **must be unique**."
3. **`Stage Level` 必须是 1–12 的数字**：原文 "Level - The level for the Stage. **A number between 1 and 12**." 文档还给出 1–12 到境界的完整映射（1–3 练气/苦修/洗髓，4–6 结丹/朝圣/洗髓，7–9 金丹/神域/孕育，10–12 元神/证道/混沌）。
4. **`Hide` 语义**：基本功法不写；进阶仙修/体修写 `1`；神修写 `2`；不打算让玩家用的隐藏功法写 `3`。
5. **`IllustratedHandLabel`**：不打算使用的功法设 `Dele`（图鉴里不出现）。
6. **`Neck.Location` 是百分比**：原文 "`1` is at the end of the stage, `0.5` is at half point"。
7. **`Neck.Kind` 枚举固定 11 种**：`None`/`Chance`/`Explore`/`Work`/`Gold`/`Thunder`/`God`/`GodCity`/`FuPractice`/`Die`。
8. **`ElementKind` 影响面很大**（这是原话的要点，非 UI 崩溃）：`GongKind` 之外，`ElementKind` 关系到"Artifact Connectivity, Cultivation/Breakthrough Timings, use in Events, Formation Requirements and Connectivity, Manual Connectivity"（见 2.2 的 EX_08 Readme 同一段）。

### 2.2 英文社区权威文档：参悟树 `Inspiration_Tree.md`

出处：https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/information/Inspiration_Tree.md

9. **节点名必须唯一**："Name - The name of the Node, **must be unique**."
10. **节点的 `Gong` 必须指向已存在的功法**："Gong - The Gong the Node belongs to. **Must be an existing Gong**."（指向不存在的 Gong，节点就无处可挂）
11. **节点的 `Level` 是枚举字符串，不是数字**："Level - The required stage, uses the `g_emGongStageLevel` values (`None`, `Qi`, `Dan1`, `Dan2`, `God`, `God2`). **Also used for the position of the node on the Y axis**." → 树的行位置由它决定。
12. **节点的 `Index` 必须是 0–11**："Index - The position of the Node on the X axis, an integer **between 0 (left most position) and 11 (right most position)**"。
13. **`Line` 是 8 个逗号分隔的整数**，顺序 `m_B0..m_B3, m_S0..m_S3`，取值只能是 `0`/`1`/`2`（画线/不画线/带箭头）。写别的数字或数量不对，线就画不出来（视觉上像"树是空的/断的"）。
14. **作者对参悟树的官方吐槽**："unless GSQ releases a tool to create them or implements them into the Content Editor, **this is the worst part about creating a custom Xiandao Gong**."

### 2.3 英文社区的完整范例（含可抄的最小可用结构）

出处：https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/examples/ACS_M_EX_08/Readme.md

15. **Stage Level 偏离原版会出意料之外的结果（原样）**："Level - To keep in line with vanilla, when there's a single Stage, use the peak value. With Four Stages, the result would be 3,6,9,12. **If you don't plan on following the vanilla values, then be prepared for unexpected results.**"
16. **节点名与秘籍名不一致要避免（原样）**："Manual Name and Node Name differences - Something that you should **avoid**, but a technical possibility."
17. **`Hide=1` 的作用**："a value of 1 will ensure that it's not shown as one of the *Locked* Laws."
18. 范例功法里同样写 `<SkillSetName></SkillSetName>` 空标签 + `<ElementKind>Shui</ElementKind>`，四段 Stage 用 `Level="3"/"6"/"9"/"12"`，Neck 分别用 `Chance`/`Gold`/`Work`/`God`——**这是已经被验证可跑通的最小闭环**。

### 2.4 中文社区（贴吧 / 3DM）

19. **功法阶段超过 9 段就显示不全（原样）**：贴吧 MOD 模板帖的实测反馈——"一、功法境界：功法境界不能删除，**游戏中最高显示9个阶段，这有12个阶段，显示不完全。（门派功法6维旁边）**"。出处 http://jump2.bdimg.com/p/8437981647

21. **BUFF 属性加成不能设负值（原样）**："3、**技能BUFF设置里属性加成不能设置负值**（比如法术吟唱时间等是需要负值的）"。（这是那个「功法创建工具」mod 的限制，未必是 XML 本身的限制，但它记录的正是编辑器作者踩到的坑。）
22. **功法文件能读能修炼，但技能树文件有问题（原样）**：3DM Cosmos069《不怎么受更新影响的稳定mod整合范例》——"再一个新功法，经过测试功法文件是可以被读取的，做完以后也可以正常修炼，**但是好像技能树那个文件有点问题**，我要再研究一下。" 出处 https://bbs.3dmgame.com/archiver/tid-5837587.html
23. **自建 XML 的读取规则（原样）**：同上帖——"游戏读取秘闻和建造列表只读取这两个文件的内容…我猜测游戏读取配置文件的规则就是**如果某文件夹下所有的文件都是控制相同内容的，那就可以读取自建文件**"。→ 新功法放 `Settings/Practice/Gong/` 下自建文件可行；`UI/MainList.xml` 这类"一个文件夹管多件事"的不能自建。

> **2026-11-18 反编译修正**：`UILogicMgr.cs:278` 调 `ModsMgr.LoadXmlDefs("Settings/UI/MainList", ...)`，`LoadXmlDefs` 对目录递归读取 `*.xml`，因此**可以自建文件**；关键是把文件放进 `Settings/UI/MainList/` 目录，不能写成同级的 `Settings/UI/MainList.xml` 文件。
24. **文本标签写法的坑（原样）**：九阳九阴归元法的词条错乱，作者要求把 `[/size]</Desc>` 里的换行补上——"找到每段中文之后，有个 `[/size]</Desc>`，在这条前面按回车，让它变成单独的一行"。出处 https://steamcommunity.com/sharedfiles/filedetails/?id=2116739388 （经搜索摘要转录）。说明**富文本标签与 `</Desc>` 的相对位置会影响 UI 渲染**。
25. **修改器「界面不出来」的官方归因（原样）**："如果发现进游戏按快捷键界面不出来，那么最大的可能是你没有激活"（指 mod 未在 mod 列表激活）。出处 https://bbs.3dmgame.com/archiver/tid-6663480.html?page=1 转录的工坊简介 + 使用指南 https://www.bilibili.com/video/av541403017/ （目录含「MOD-物品添加(物品,法宝,功法,秘籍,符咒)」「MOD-人物管理(功法秘籍)」）。

## 5. 对「空 SkillSetName / Stage Level 非标准值 / ElementKind=None」的外部佐证

### 5.1 空 `SkillSetName` —— 有明确说法：**空才是正确写法**

- 权威文档明写："SkillSetName - **Not used, leave it as it is.**" —— https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/information/Laws(Gong).md
- 官方范例也写空标签：`<SkillSetName></SkillSetName>` —— https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/examples/ACS_M_EX_08/Settings/Practice/Gong/ACS_M_EX_08_Gong1.xml
- 本机原版普查：17 个含 `SkillSetName` 的 XML **全部为空**（含 `Gong_1..12`、`Gong_Lost`、DLC 武当、灵兽/妖兽/丹药各派），非空值零命中。
- **结论**：把它当成"面板空白的元凶"缺乏依据；把它填上自定义字符串反而没有任何文档支持其语义（"未使用"意味着游戏不读）。

### 5.2 `Stage Level` 非标准值 —— 有明确说法，且**确有显示不全的实测**

- 硬约束原话："Level - The level for the Stage. **A number between 1 and 12.**" —— 同上 `Laws(Gong).md`。文档还给了 1–12 的完整境界映射表（1–3 练气，4–6 结丹，7–9 金丹，10–12 元神）。
- 偏离原版的风险原话："**If you don't plan on following the vanilla values, then be prepared for unexpected results.**" —— https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/examples/ACS_M_EX_08/Readme.md
- 阶段过多会**显示不全**（不是崩溃）："**游戏中最高显示9个阶段，这有12个阶段，显示不完全。（门派功法6维旁边）**" —— http://jump2.bdimg.com/p/8437981647
- 本机原版普查：`<Stage ... Level="N">` 的 N 全为 1–12 的数字，最常见 `3`/`6`/`12`/`9`。
- **结论**：`Stage Level` 必须落在 1–12；写 `Qi`/`Dan1` 这种字符串是把**参悟树节点**的 `Level` 枚举误用到了 **Stage** 上（两处同名不同义，是这类坑的高发点）。段数超过 9 段时界面显示不全，有实测佐证。

### 5.3 `ElementKind=None` —— 没有负面说法；`None` 是原版合法值

- 文档只说："ElementKind - The element of the Gong, **usual values apply here**."，且同页的 `Gong_Lost` 示例本身就写 `<ElementKind>None</ElementKind>` —— https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/information/Laws(Gong).md
- 本机原版普查：`ElementKind` 分布 Huo 3 / Jin 2 / Mu 2 / **None 7** / Shui 1 / Tu 2 —— `None` 是用得最多的取值之一。
- 已发布 mod 亦如此：剑来功法「诗经」用 `None`，诸天万法「分诀」用 `Huo`。
- 文档强调它的真实影响面是**玩法耦合**而非 UI："The Element of Law has multiple aspects. **Artifact Connectivity, Cultivation/Breakthrough Timings, use in Events, Formation Requirements and Connectivity, Manual Connectivity**, the impact of a single string is major." —— https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/examples/ACS_M_EX_08/Readme.md
- **结论**：`None` 不会让界面空掉；它会让该功法在五行相性/阵法/法宝/秘籍匹配上"无属性"。若担心的是"参悟树空白/面板空白"，应当去查 5.4 的两条。

### 5.4 真正能造成「参悟树空白」的两个字段（外部有明文，内部有调用链印证）

- **节点 `Level` 写错枚举**：必须是 `None`/`Qi`/`Dan1`/`Dan2`/`God`/`God2` 之一，且"Also used for the position of the node on the **Y axis**" —— 写数字或写错值，节点就落到不存在的行上。出处 https://github.com/iguanacore/acs-modding-guide-iguana/blob/main/information/Inspiration_Tree.md
- **节点 `Index` 越界**：必须是 "integer between **0** (left most position) and **11** (right most position)" —— 超出 11 就超出 12 格的可视范围。出处同上。
- **节点 `Gong` 指向不存在的功法**："**Must be an existing Gong.**" —— 出处同上。
- **`Line` 数量/取值不对**：只能是 8 个 0/1/2，否则线画不出来，整棵树在视觉上就是"空的/断的"。出处同上。
- 与本地引擎调用链印证（**本地反编译结论，非外部 URL**）：`Wnd_GongSkillTree.UpdateDate` 用 `m_tree.GetChildAt((int)(def.Level - 1))` 取行、`m_n144.GetChildAt(def.Index)` 取格（每行 12 格）。即：**`Level` 决定行、`Index` 决定列，两者任一越界 → 该节点不可见，整棵树只有图标没有内容或干脆一片空**。这与上面四条外部规则完全一致，属于本项目自己的取证，不作为社区佐证引用。

## 6. 给《功法配置规范》的直接结论（一页速查）

1. `SkillSetName` 保持空标签，**不要**往里填东西；它不是坑。
2. `Stage/@Level` 只能是 **1–12 的整数**；不要写 `Qi`/`Dan1`（那是参悟树节点的枚举）。段数尽量 ≤9（超过会显示不全），四段式用 3/6/9/12。
3. `ElementKind` 用 `Jin/Mu/Shui/Huo/Tu/None`；`None` 合法且原版常用，影响的是玩法耦合而非 UI。
4. 参悟树：`Node/@Name` 唯一、`Node/@Gong` 必须存在、`Level` ∈ {None,Qi,Dan1,Dan2,God,God2}、`Index` ∈ 0–11、`Line` 恰 8 个 0/1/2、`Skills/li@Name` 与秘籍、Modifier 同名对齐。
5. 富文本 `[size][color]` 与 `</Desc>` 之间**留换行**，别挤在一行（有 mod 因此词条错乱，作者给出了手工修复法）。
6. 依赖别的功法 mod（如太古鸿蒙诀）时，在 `Info.json`/README 里写明，并考虑用 mod 依赖/加载顺序声明；同时提醒玩家**新旧版本不保证兼容**。
7. 与「MOD版修改器」共存：若必须同用，**兼容助手在首位、修改器在第二位**；排查任何"面板数值/境界不对"先摘掉修改器做 A/B。
