# 万法阁 · 衍天诀 设计方案（v0.1 草案，待确认）

> 目标：为《了不起的修仙模拟器》做一个可持续扩展的**综合功法 mod「万法阁」**，第一门功法为仙修「衍天诀」。
> 本文是动工前的方案与数值初稿，带 ❓ 的条目需要你拍板，带 ⚠ 的是实现风险点。

---

## 0. 设计定位

衍天诀的差异化不在"打伤害"，而在**资源循环**：
- 用「解析」把世界里的物品变成**永久素材库**（信息 → 资产）；
- 用「创造」把素材库变回物品（资产 → 物资）；
- 用两件专属法宝把个人素材库/灵气**汇成宗门级总库**（个人 → 集体）；
- 用「避天机」把"到点必须渡劫"变成**玩家自己决定何时飞升**（时间 → 选择权）。

一句话：**它是一门"越玩越富、越拖越强"的功法**，前中期靠自愈与法宝格站住，后期靠总库滚雪球。

- 独立新 mod 目录（**不动**旧的 `诸天万法`），Name = `万法阁`。

### 1.3 已有技术结论（已核实）
- 参悟树节点 `<Esoterica>` 可以直接填**秘籍名**，而秘籍（`Type=Skill`）用 `<Magics><li>…</li></Magics>` 授予神通 —— 所以「自愈程序/衍天/避天机」的**学习入口 = 参悟树节点**，玩家花参悟点解锁即得对应神通。
- 游戏内已有 `Wnd_InputPanel`（`ShowInputPanel`/`HideInputPanel`）、`Wnd_ItemSelectCommon`、`UI_TianJieBtn`、`NpcPractice:BeginJieNan`，UI 与飞升都有原生入口可借。
- 属性 `NeckCountdownAddV`（瓶颈倒计时推迟时间，Max 99999999 秒 ≈ 3.17 年）、`NpcFight_FabaoNum`（法宝格）、`MaxAge`、`NpcLingMaxValue`、`DeepPracticeSpeedSpecialCoefficient`、`InspirationCoefficient` 均存在。

### 2.2 衍天佩（手工台装备）

**定位**：衍天诀的专属佩饰，把「已学技能」转成可叠加的佩版增幅（多数为原效果 2 倍）。它不是技能树节点，而是一件手工台装备，解决「技能学了但数值不够直观」的问题，也给玩家一个把衍天诀技能全点满的长期目标。

**物品与配方**
- `Settings/ThingDef/Item/Item_YanTian.xml` 新增 `WFG_Item_YanTianPei`：`Parent=ToolBase`、`Item Lable="Tool" Kind="Equipment"`、`MaxStack=1`、`Beauty=15`、图标 `Spr/Object/wfg_item_yantianpei.png`（源图 `res/img_item_yantian_yantianpei.png` 为 360×360 RGB 且棋盘格背景已烘焙进像素，已抠成 128×128 RGBA，内容区域 104×96，透明背景）。
- `BeMade`：`WorkToMake=300`、`Quality=0`、`StuffCategories` 同时列 `Wood` 与 `WoodBlock`、`CostStuffCount=10`、`CostItems` 为 `WFG_Item_YanTianZhu` ×1。任意木料与木块都可作为木料消耗；另用 `ProduceMode` 的 `ProduceBuildings` 注册到 `HandWorkTable`（游戏内「手工桌」），使 `BeMade` 配方进入手工桌列表。
- 装备槽：`Lable=Tool` 走 `Npc.CheckEquipCell` 的 default → `GetToolEquipCell`，实际落在 `Tool1..Tool10`（1001..1011）。`pei.lua` 先走 `WFG.item:IsEquipped`，失败再自行扫 1001..1011，避免只扫法宝槽漏判。

**14 项解锁**
- 解锁判定统一为「佩带衍天佩 + 已学对应秘籍」；`Scripts/Gong/YanTian/pei.lua` 的 `SKILLS` 表列出 14 项：gong/heal/healPlus/derive/create/fabao/guard/lingStone/sword/shield/codex/cycle/edge/undying。
- 9 个被动 Modifier 在 `Settings/Modifiers/Modifier_YanTian_Pei.xml`：`WFG_Mod_YanTian_Pei_Gong/Fabao/Guard/Sword/Shield/Codex/Cycle/Edge/Undying`。其中 Sword/Shield/Codex/Cycle/Edge/Undying 与 `Modifier_YanTian_Tree.xml` 对应项同值，Gong 与原 S1 同值，Guard 与原 Guard 同值；Fabao 原节点只解锁配方，佩版额外 +100% 法宝威力（`AddV=1`）。因此已学 + 佩带时，Gong/Guard/六项技能合计为原效果 2 倍，Fabao 为额外增幅；只佩带未学不生效。
- `P:Sync` 只做两件事：按 14 项状态加/删 9 个 Modifier；按「佩带 + 已学炼石」`AddMagic`/`RemoveMagic` 提供主动神通按钮。它**从不调用 `MagicEnter`**，不会自动施法。
- 生命周期：`module:OnSecond` 对 `WFG.npc.list` 调 `P:SyncAll`；`OnStageChange` 调 `P:Sync`；`OnEnter` 清理运行时状态；`OnLeave` `P:ClearAll`。加载顺序未定时 `module.lua` 对 `WFG.YanTian.pei` 判 nil。

**数值与公式**
- 总纲：佩版 `NpcLingMaxValue AddP=1`，与原 S1 的 `AddP=1` 相加，合计 +200% 基础灵气。
- 自愈：`H:Pct` 先取境界基础 `HealPercent`；精研原书 +0.5，佩解锁精研再 +0.5，合计 `mult=1+bonus`；佩解锁自愈再 `mult×2`。只学精研 = ×1.5；精研+佩 = ×2.0（自愈未学）；自愈+精研+佩 = ×4.0（基础×2 × 精研×2）。
- 解析/创造：`D:DeriveCost(level, quality, npc)` 在佩解锁解析时 `cost=floor(cost×0.5)`（最低 1）；`D:CreateCost(level, quality, count, npc)` 内部用**不传 npc**的 `DeriveCost` 算基价，批量折扣后再对佩解锁创造 `×0.5`，避免解析与创造同时解锁时叠成 ×0.25。`derive.lua` 的 6 处调用与 `main_window.lua` 的报价均已传 `npc`。
- 炼石：新增 `Settings/Practice/Magic/Magic_YanTian_Pei.xml` 的 `WFG_Magic_LingStoneMake_Pei`，`Param1=10`、`CostLing=5000`、`CostAge=0`、`CMD=AbsorbGong_11`。佩带并已学炼石时只把该神通加入技能栏；玩家点击后引擎沿用原版 `ToilAbsorbGong`，每 10 秒掉 1 枚 `Item_LingStone`，进入先扣 5000、之后每枚再扣，灵气不足或停止即结束。原 `WFG_Magic_LingStoneMake`（20 秒/枚）保留，两个按钮可并存。

**表现**
- 主面板「总览」在本命法宝行后显示：未佩戴 → 「衍天佩：未佩戴（手工台：1 衍天珠 + 10 任意木料）」；已佩戴 → 「衍天佩：已佩戴（已学 x/14）」+ 已解锁项摘要。只读展示，不在面板内施法。
- 物品 `Desc` 写全 14 项与主动炼石说明；README 同步配方、解锁表与炼石主动化。

**边界**
- 旧档没有衍天佩：需要手工台重做；已学技能记录不受影响。
- 佩带期间点击炼石（佩）后卸下：引擎不会立即中断已在运转的 Toil；再次点击停止/灵气不足自然结束。Lua 不强制打断，避免和玩家手动停止冲突。
- 敌人若通过交易/掠夺拿到衍天佩，也会按自身已学技能解锁；本设计不绑定阵营，强度来自「衍天诀技能 + 珠子成本」，不靠隐藏物品。

**灵子飞升（第 6 层突破）一次性永久增益**：
- 寿元 `MaxAge` **BAddP +300%**
- 灵气上限 `NpcLingMaxValue` **BAddP +200%**
- 修炼速度 `DeepPracticeSpeedSpecialCoefficient` **AddV +2**
- 领悟悟性 `InspirationCoefficient` **AddV +1**
- 灵气吸收 `LingAbsorbSpeed` **AddP +100%**
- 法宝格 `NpcFight_FabaoNum` **AddV +1**

**自愈程序**：以「回灵速度」形式生效——每秒结算一次，把 灵气 4% / 血量 1.5%（自飞升层起每高一层 +0.5% / +0.2%）折算成 点/秒 的回灵速率发布给引擎，人物面板灵气行直接显示 +X/秒；灵气满后溢出部分转补血量。精研本在金丹期学习。

### 3.1 灵子飞升（XML 为主）
- 1~3 层：`Neck Kind="Chance"`，正常突破。
- 第 4 层：`Chance` + `<ItemCost>`/`<ResourceCost>` 或 `SuccessChange` 表达式要求"灵气足够"，`<AddModifier>` 挂灵体永久增益。
- 突破后 `Stage` 的 `Value` 里给法宝格与后续门槛。
- 备用方案：若 XML 表达不了"灵气 ≥ 5000 才能突破"，用一个 Lua 神通「灵子飞升」做主动突破（消耗灵气 → 直接调境界推进），XML 的 4 层颈做成"不可突破"的展示位。

### 3.1.1 飞升的双结局（已定）
渡劫成功后有两条路，由玩家在「渡劫」面板里**先选后渡**：
- **留世**（默认）：角色留在门派，境界到 12 层「天门·真仙」，保留全部属性与总库权限，可继续经营/战斗。
- **登仙离场**：走原版飞升表现（角色离开地图，留下传承/遗蜕），世界记一笔"某某飞升"，其余角色与总库不受影响。
- 两者都要求：已学「避天机」或主动点「渡劫」；区别只在渡劫前的选择。

### 3.2 自愈程序（Lua，每秒结算 + 每帧发布速率）
- 学会秘籍后每秒对"修炼衍天诀且已学自愈"的角色结算一次，把灵气回复折算成 **点/秒** 的回灵速率：
  1. `rate = min(MaxLing * pctLing, 灵气缺口)`，用 `npc:DynamicAddLing(基值 + rate)` 发布；
  2. 引擎每帧按 `DynamicLing * dt` 自行加灵气（`XiaWorld/Npc.cs:5706`），因此人物面板灵气行的 `+X.XX/秒`（`Panel_ThingInfo.cs:2801`）就是真实恢复速度；
  3. 地脉吸灵（`LingMapData`，16Hz）会覆盖 `DynamicLing`，所以用 `WFG:OnStep` 每帧重新叠加；`基值` 由"值被外部改写"自动检测，环境吸灵贡献不丢失；
  4. 灵气满时速率归零，原本的回灵份额按溢出比例转为 `AddHealth`（最多翻倍）。
- 基础 4%/1.5%，每提升 1 境 +0.5%/+0.2%，精研 ×1.5。
- 关闭开关 / 离开地图时把 `DynamicLing` 写回原值，不留残留加成。
- 可开关（热键或神通开关），避免和"想靠空灵气触发某些机制"冲突。

### 3.3 避天机程序（Lua + 属性）
- 学会后给角色挂永久 `NeckCountdownAddV` **+99999999 秒**，并在 `OnStep` 里做"续期"（每 30 秒检查一次，若剩余 < 阈值就补满），等效**冻结倒计时**。
- 同时解锁神通「渡劫飞升」：玩家主动点 → 弹出「留世 / 登仙」二选一 → 调 `NpcPractice:BeginJieNan()`（⚠ 需实测签名，备选 `UI_TianJieBtn` 同款入口）。
- 未学避天机：11 境后倒计时照常走，到点自动天劫 —— 与原版一致，保证"不学就正常飞升"。
- 天劫结算：胜则按 3.1.1 的选择走留世/离场；败则重伤/跌境（沿用原版惩罚，不额外加码）。

### 3.4 衍天（核心玩法）

**解析**
1. 玩家用神通「衍天·解析」选中一个物品（复用引擎物品选择；⚠ `SelectType` 可能是枚举，需实测哪个值等于"选物品"）。
2. 校验：物品可解析（黑名单：任务物品/剧情唯一物/已解析）；角色境界 ≥ 该物品要求。
3. 扣灵气 → 把 `ThingDef.Name` 写入该角色的素材库（**per 角色，永久**）。
4. 弹出提示：新收录 / 已收录（已收录则不消耗灵气）。

**要求与消耗公式**（`L` = 物品等阶 `Level`，`Q` = 品级 `Quality` 1~5）
- 可解析上限：`Lmax = 2 + (境界层 - 4) * 1.2`（4 层 ≤2，8 层 ≤6，12 层 ≤11）
- 解析消耗：`Cost = 50 * (L + 1)^2 * Q`
  - L0Q1 ≈ 50；L5Q3 ≈ 5400；L10Q5 ≈ 30250
- 已解析物品：重复解析**免费**，只提示"已在库中"。

**收录粒度（已定：按物品定义）**
- 素材库以 `ThingDef.Name` 为唯一键；同种物品只占一条，**永远只解析一次**。
- 首次解析记录该物品的**品级 Q**；之后再解析同种但更高品级的物品，**免费**把记录品级提升到更高者（"解析得更透彻"）。
- 创造时按记录的品级产出；低品级物品也能造，但品级不会超过记录值。
- 面板显示：`名称 · 等阶 L · 已解品级 Q · 单件消耗`。

**创造**
- 单件消耗 = 解析消耗 × **30%**；批量 n 件 = 单件 × n，n ≥ 10 打 **9 折**，上限 100/次（10 境解锁）。
- 产出：直接落到角色脚下/门派仓库（可配置）；创造出的物品是**全新普通物品**，不带原物品的品级溢出（品级按素材库记录的 Q 还原）。
- 特殊物品（神器/唯一物）默认**不可创造**，但可"解析收藏"（只进图鉴不产出）。

**素材库 UI**
- 按等阶分组的分页列表（每页 8~10 条），每条：名称 / 等阶 / 品级 / 单件消耗 / [造 1] [造 10]；
- 顶部筛选：全部 / 可造 / 仅收藏；
- 底部：「解析新物品」「创造」入口。

### 3.5 本命法宝
- 法宝格：飞升后每境 +1（见境界表），用 `NpcFight_FabaoNum` 永久增益实现；累计 6 格。
- 本命法宝 = 装备后额外提供"衍天诀专属能力"的真实法宝；v1 两件：灵析剑（素材）、灵源剑（能源）。
- 官方炼制：秘籍只新增 `<Fabaos>` 配方引用，炼制完全走游戏原生炼器；Lua 不再提供一键炼制入口。
- 佩带判定：`Scripts/WFG/item.lua` 的 `EquipState` 遍历 `FABAO_SLOTS={1,2,81..85,1001..1006}` 逐个 `npc.Equip:GetEquip`（法宝槽 + 武器槽 1 兜底 + 秘宝实际所在的道具槽 Tool1..6），按当前定义名或 `Fabao.Oitem` 识别（认主后原剑会变成通用 `FightFaBao`），返回 `equipped/inactive/none/unavailable`；未认主的法宝胚胎（`FabaoAcriveData ~= nil`）判 `inactive`，界面显示「待认主」并锁住功能；全槽接口异常才判 `unavailable`。
- 管理界面：不再用神通按钮。两座奇观建筑各带一条 `StoryBnts`「管理」：数据中心直接 `WFG.ui.hallMat:Open(bind)`；能源中心 `WFG.ui.hallEng:SelectNpc(bind)` 先选人。对应 `Scripts/WFG/ui/hall_window.lua` 的两个独立 `FairyGUI.Window` + `InGame.RemoteStorage` 壳（contentPane 470×524）：数据中心用 4×3 物品卡片网格展示素材（图标/名称/品质、悬停浮窗、顶部类别页签 + 品质/品阶/五行三枚下拉筛选（自动分两行，点击展开二级浮窗）），只显示收录种数与座数，不显示角色；能源中心用同一壳的空白面板（428×428 内容区），正文先固定满宽再居中，三条 `UI_SliderH` 调整补灵阈值/取用限额/单次取用，主操作与底部按钮按可见项居中。能源窗先用 `Wnd_SelectNpc` 选人，佩带已认主灵源剑的衍天诀角色也可从指令栏直接打开；非衍天诀角色选人后被门禁拦截，只弹提示、不显示能源窗。两窗都用 `CenterOn` 居中，筛选与模式切换均走二级浮窗，展开后可点击空白关闭；创造页卡片只显示品质、不显示库存数字。按钮用精确尺寸的自绘扁平控件，避免原生按钮图形越界。
- 属性加成：`hall:SyncBuff` 每秒核对「功法=衍天诀 且 佩带对应剑」，状态变化时才 `AddModifier` / `RemoveModifier`；两件可叠加，卸下或转功法立即移除。
- 认主条件：两剑的 `<Fabao>` 各带一条 `<ActiveCondition><Condition eventid="Other" des="修行衍天诀" needcount="1"/></ActiveCondition>`。新炼出的剑由 `ItemThing.OnInit` 自动生成 0/1 条件；`module:TickFabao` 每秒只对衍天诀角色调 `FabaoEventMgr.SetFabaoActive(..., Other, 1)` 推到 1/1，其他功法永远停在 0/1，装备面板不能点认主。`EnsureFabaoCond` 作为旧档兜底：读档时 `OnInit` 已会按 `ActiveCondition.Count` 重建空 `Actives`，仅当某把未认主的剑仍未带条件时才补一条。**认主后原剑由 `ActiveFabaoEmbryo` 换成通用 `FightFaBao`，原定义名保存在 `Fabao.Oitem`**；`EquipState` 同时匹配当前定义名与 `Fabao.Oitem`，所以已认主剑仍判 `equipped`。已认主剑没有 `FabaoAcriveData`，不参与激活推进，也不回退绑定。装备读取走 `npc.Equip:GetEquip`（`Npc.GetEquip` 也存在，等价转发）。秘宝/本命法宝胚胎的 `Lable=Treasure` 在 `Npc.CheckEquipCell` 没有专门分支，走 `default → GetToolEquipCell`，实际装在道具槽 `Tool1..Tool6=1001..1006`；槽位表漏掉这一段时 `pcall` 读不到剑，表现为进度永远 0/1。

### 3.6 两件专属法宝

**灵析剑（衍天数据中心）**
- 获取：学会「本命法宝·总纲」解锁 `WFG_Formula_HallMat`，走官方法宝炼制，产物 `WFG_Item_HallMatFabao`，先装入人物道具槽并右键认主；配方需 **3 颗衍天珠 + 10 灵石**。
- 功能：**没有手工汇入/取用按钮**。佩带后个人素材库与共享素材总库每秒双向并集同步：
  - 个人 → 总库：只推真正自有的条目（`own ~= false`），品级/等阶取高、材料与品级集合并集；
  - 总库 → 个人：新增条目写入个人库并标记 `own=false`（借用）；已有条目只做并集，不翻转自有标记；
  - 卸下/转功法：`ClearShared` 删除 `own=false` 的借用条目，自己解析的保留；
  - 自己重新解析某条借用素材时，该条转为自有并回推总库；
  - 版本机制：`world.hallMat.ver` 与 `c.libVer` / `c.sharedVer` 比对，多佩带者下一秒自动拉取；存档素材字符串扩为 7 段，第 7 段记录 `own`（旧 6 段按自有处理）。
- 只有**修炼衍天诀且佩带该剑**的角色参与同步；其他功法佩带 = 普通法宝。

**灵源剑（衍天能源中心）**
- 获取：学会总纲解锁 `WFG_Formula_HallEng`，走官方法宝炼制，产物 `WFG_Item_HallEngFabao`，先装入人物道具槽并右键认主；配方需 **9 颗衍天珠 + 100 灵石**。
- 存入 / 取用：能源中心提供「存入一半」「取用一半」；只有衍天诀且佩带灵源剑时可用。参数滑条可调整该角色自己的补灵阈值（10%–90%）、累计限额（10 万–1000 万）、单次取用（1 千–100 万），并可用二级浮窗切换供灵模式、用按钮重置已用；参数管理只要求衍天诀，未佩剑也可预设。
- 自动供灵两种模式：
  1. **实时获取**：自身灵气低于阈值（默认 60% 上限）时补到阈值；累计取用达限额（默认 100 万）后停止，需重置或切模式。
  2. **充满获取**：自身灵气见底时一次取设定量（默认 1 万）。
- 核心容量上限默认 **1 亿**，存满后拒绝存入并提示。
- 供灵在 `hall:Second` 每秒结算，战斗/日常同一套逻辑。

### 3.7 衍天珠

**定位**：衍天诀专属凝练物，同时是消耗品、佩带物与两柄本命飞剑的核心炼器材料。

**产出**：神通「凝练衍天珠」（`WFG_Magic_NingZhu`）由功法 `WFG_Eso_YanTian_Gong` 的 `<Magics>` 授予；点击打开 `WFG_NingZhu` 窗（560×380）。滑条取 1..min(999, floor(当前灵气 / 500))（只有 1 档时锁定为 1；滑条 max 至少给 2，避免出现 -nan(ind)），确认时先扣 `n × 500` 灵气，再用 `WFG.item:Create("WFG_Item_YanTianZhu", 3, n, npc)` 产出 n 枚；造物失败则退回灵气并提示。`EnableCheck` 限定衍天诀角色，物品本身不设 `BeMade`，避免被其他途径批量生产。

**物品**：`WFG_Item_YanTianZhu`（`Parent=DanBase`，`Item Lable="Dan"`，`MaxStack=99`，可堆叠；图标 `Spr\Object\wfg_item_yantianzhu.png`，由 `make_icons.py` 从 `res/img_item_yantian_yantianzhu.png` 按 alpha 裁边，内容缩到 64×64 后居中贴到 128×128 透明画布，四周留白，避免背包格内显得过大）。

- **服用**：`<Elixir><Modifier>WFG_Mod_YanTian_ZhuUse</Modifier></Elixir>` 只挂一个不入档的标记 Modifier（`MaxStack=99`、`Duration=-1`、`Display=0`）。**`MaxStack` 必须 > 0**：`NpcPropertyMgr.AddModifier` 只在 `m.def.MaxStack > 0` 时把实例登记进 `m_lisModifiers`，写 0 会让 `FindModifier` 永远读不到层数；同名重复 AddModifier 会合并到已有实例并 `UpdateStack`，层数即服用颗数。`module:TickZhu` 每秒经 `NpcLuaHelper:GetModifierStack` 读层数（**原始 `Npc` 上没有该方法绑定**，直接 `npc:GetModifierStack` 会抛异常被 pcall 吞掉，表现为「吃了没反应」）：每一层按**当前**最大灵气回复 10%，前 4 层递增 `c.zhu` 并立即补上永久加成，最后清空标记。同秒连服多颗不会丢层。
- **筑基**：`<Elixir><ZhuJi>10000</ZhuJi>`。`Npc.EatItem` 仅在 `Rank != Disciple`（尚未入门）且智慧种族时调用 `Practice.AddZhuJi`；筑基总额 25000，故一颗约 40%。不能写 `DiscipleOnly`——它要求食用者已是弟子，而弟子 `LogicStage > 0` 时 `AddZhuJi` 直接 return，两者互斥。
- **永久加成**：`WFG_Mod_YanTian_ZhuLing1..4` 四个独立 Modifier，均 `MaxStack=1`、`Duration=-1`、`Display=0`、`NpcLingMaxValue BAddP=0.25`；按 `c.zhu` 补齐 1..N、移除多余层，避免依赖同名 Modifier 叠层。`BAddP` 作用在基础值上，4 层合计 +100% 基础灵气。
- **佩带**：`<Equip><ToolModifier>WFG_Mod_YanTian_ZhuEquip</ToolModifier></Equip>`，Modifier 给 `MindStateBaseValue AddV=100` 与 `RecoveryPower AddP=0.5`（伤势自然恢复 +50%，由 `NpcBodyData.Step` 每 0.5 秒按 `GetPropertySecond("RecoveryPower")` 结算）；引擎没有自然回血/回灵属性，气血与灵气由 `module:TickZhuWear` 每秒 `AddHealth(MaxHp×0.3%)` / `AddLing(MaxLing×1%)` 补足，佩带状态用 `NpcLuaHelper:GetModifierStack` 判 `WFG_Mod_YanTian_ZhuEquip`；卸下即移除。
- **存档**：`c.zhu` 取 0..4，旧档缺省 0；`SyncZhuMods` 用不入档的 `_zhuOn` 只做本次会话去重，读档后按存档层数重新补齐。
- **聚灵**：物品根下 `<Ling>` 使用原版最高档聚灵模板：`AddionLing=200`、`AddionRadius=2`（5×5）、`AddionFailing=0.95`、`AddionFailRadius=1`、`Attenuation=0.1`、`Absorption=0.8`、`Accommodate=40`。放到地图格时生效，随身佩带/背包不生效。游戏 tooltip 的「范围」是半径，2 即 5×5；不要按格数理解。

**配方替换**：`Settings/ThingDef/Item/Item_YanTian.xml` 中两剑 `BeMade/CostItems` 的 `Item_SoulPearl`（玄牝珠）已替换为 `WFG_Item_YanTianZhu`，数量 3 / 9 不变；原玄牝珠不再参与本命法宝炼制。

### 3.8 衍天数据中心与衍天能源中心（奇观建筑）

两座共享建筑不再是参悟树技能，改为**奇观**建筑：选择任一「万法阁」开局经历（`WFG_Exp_` 前缀，如「万法阁·衍天传人」「万法阁·衍天遗泽」）后自动解锁，入口在「建造 → 奇观」。

- 定义：`Settings/ThingDef/Building/Building_YanTian.xml`，两件均 `Parent=OrnamentBase`，不带 `_WONDER` 标签、不继承应天台的「观摩」故事按钮。
- 形制：衍天数据中心取应天台（`building_jianlingtai01a`，2×2，Rate 6，Shadow 1×1.5，`Orientation F,R`）；衍天能源中心取灵玉峰（`Spr/Object/wfg_building_lingyufeng.png`，从原版 `building_lingyufeng01` 提取后随 mod 分发，5×3，Rate 12，Shadow 1×1.2，**不写 `Orientation`**）。两者 Beauty 25、MaxHitPoints 3000、NoElementKind 1、BlockLight 0、Flammability 0、AutoUnLock 0。
  - 能源核心不能写 `Orientation F,R`：`BuildingData.Orientation` 为空时会自动补 `Right` 并把 `AutoOrientation` 置 1；一旦显式写 F/R，`GMyLoader.LoadThing` 和 `BuildingView` 会给贴图路径追加 `_F` / `_R`，自定义 PNG 没有这些后缀就会显示空白/「无」。不写 Orientation 时 `AutoOrientation=1`，引擎不追加后缀。
- 建造：材料只收 `MetalBlock`（任意金属锭）`CostStuffCount=999`，另 `CostItems` 衍天珠 ×9；工作 3000 / 6000，Quality 0。
- 管理入口：两建筑各带 `StoryBnts`「管理」；`Panel_ThingInfo.OnClickStoryBnt` 对非空 `Script` 直接 `NpcDoLua(null, script, {bind=thing})`，不进入原版故事/指派流程。数据中心直接打开；能源中心先用 `WorldLua:GetSelectNpcCallback` + `Wnd_SelectNpc:Select` 选人，再用 `ThingMgr:FindThingByID(rs[0])` 解析角色。
- 解锁：`Settings/UI/MainList/MainList_YanTian.xml` 两条为 `Unlock="0" Type="奇观"`。引擎显示条件为 `Unlock <= SchoolMgr.UnLockLevel` 且（`AutoUnLock > 0` 或 `IsBuildingInUnLockList(name)`），所以可见性完全由解锁列表控制。
- Lua：`NpcExperienceDef` 没有 Buildings 字段，选择经历不会直接解锁建筑；`module.lua` 的 `EnsureHallUnlock(npc)` 每秒遍历 `npc.PropertyMgr.ExperienceList`，命中 `WFG_Exp_` 前缀的万法阁经历后对两座建筑调 `WorldLua:UnlockBuilding(name)`（先 `IsBuildingUnlocked` 判重，幂等），成功后按 npc 缓存，读档/离开重置。
- 旧秘籍 `WFG_Eso_YanTian_HallMat` / `HallEng` 的定义保留并加 `<Hide>1</Hide>`：旧档若已学，`NpcPractice` 读档会逐条调 `EsotericaFinish`，直接删 def 会让 `GetEsoterica(id)` 返回 null 并触发空引用。它们没有树节点、没有 `<Magics>`、没有获取入口，`Hide=1` 也不会出现在秘籍列表。

## 5. UI 方案（已定：FairyGUI 精致界面，代码构建）

> 具体设计规则与验收见 [UI 设计规范](UI设计规范.md)；本节只保留方案结论。

**结论：不需要 FairyGUI 编辑器，也不需要美术资源。** 游戏把所有 FairyGUI 类型都暴露给了 Lua（`Scripts/flua.lua` 里 `GComponent / GList / GTextInput / GButton / GGraph / GProgressBar / GComboBox / PopupMenu / ScrollPane / TextFormat` 全部可用），因此可以：

- `Windows:CreateWindow("YanTianLib")` → `SetSize` → **用 `GComponent` / `GGraph` / `GTextField` 现场拼出 `contentPane`**；
- 面板底色/分隔线用 `GGraph:DrawRoundRect` / `DrawRect`（纯色填充，无贴图依赖）；
- 按钮与标题栏**复用游戏原版组件 URL**（`ui://0xrxw6g7hdhl18` 按钮、`ui://0xrxw6g7nd594l` 标签等），保证和原版视觉一致；
- 数字输入用 `GTextInput`（真输入框，支持光标与键盘），不用再借 `Wnd_InputPanel`；
- 列表用 `GList + ScrollPane` 做滚动，或用 `GComponent + 上下翻页按钮`（更稳的兜底）；
- 模式切换/数量预设用 `GComboBox` 或 `PopupMenu`。

**窗口清单（v1）**
| 窗口 | 内容 |
|---|---|
| 衍天·凝练衍天珠 | 当前/上限灵气、可凝练颗数、滑条选 1..N（1 档时锁定）、本次消耗、服用/佩带说明、已服层数、[凝练][取消] |
| 衍天·素材库 | 左侧等阶分组、中间物品列表（图标+名称+品级+消耗）、右侧详情与 [造1][造10][造100]、底部搜索/筛选/总库入口 |
| 衍天·总库（藏） | 总库素材网格、上传/取用、容量与贡献者列表 |
| 衍天·能源核心 | 核心余量进度条、存入（数量/比例）、每件终端法宝的模式卡（实时/充满 + 输入框 + 限额重置） |
| 衍天·渡劫 | 天劫状态、留世/登仙二选一、确认按钮 |

**风险**：xLua 是否绑定了「无参构造 + 事件委托」。M0 必须先做 **UI Spike**：在游戏里代码建出一个带按钮、文本、输入框、滚动列表的小窗口并打日志验证；若构造不可用，降级为"复用原版组件 URL + 手动布局"，仍比 SimpleWindow 精致；再不行才退回 SimpleWindow。

## 8. 已确认决策

| 项 | 决定 |
|---|---|
| 素材库粒度 | **按物品定义**收录；记录并只升不降地保存最高品级 |
| 飞升去向 | **双结局**：默认留世继续玩，渡劫前可选登仙离场 |
| 强度档位 | **明显超模**（灵析/灵源大幅提升属性，仅衍天诀生效；法宝格 6 格） |
| UI | **FairyGUI 代码构建的精致界面**（不需要编辑器与美术资源，M0.5 先验证） |
| 功法获取 | **开局可选 + 藏经阁「衍天诀·总纲」秘籍** |

### 仍需确认（不答则按推荐执行）
1. **入口形式**：总库/素材库面板挂在①神通（点神通开窗）②全局热键 ③点击总库建筑 —— 推荐 **①+②**，建筑点击放 v2。
2. **NPC 能否学衍天诀**：能学会让 NPC 也攒素材库（世界更活，但性能与平衡风险↑）；推荐 **仅玩家门派角色自动学，敌方 NPC 不学**。
3. **门派风味**：衍天诀是否需要绑定一个"万法阁"势力/门派（自带专属建筑与传承），还是作为可被任何门派学习的功法 —— 推荐 **先做功法，势力留到第二门功法时再加**。
